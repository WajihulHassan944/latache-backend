# Security controls

- Passwords use bcrypt with configurable cost and are never serialized.
- Email verification and password recovery use independent expiring OTP fields with persisted attempt limits.
- Password recovery is OTP-only; no reset JWT or query-string token compatibility exists.
- Access tokens are accepted only from the `Authorization: Bearer` header.
- Every bearer request revalidates the user and active session in PostgreSQL.
- Refresh tokens are opaque, stored only as SHA-256 hashes, rotated transactionally and protected against reuse.
- Password reset and password change revoke all sessions.
- Public resend/recovery endpoints use anti-enumeration responses.
- Administrator creation is restricted to the canonical super admin; permissions are validated against a server-owned catalogue.
- SMTP calls are awaited, failures are surfaced, and OTP/password values are not logged.
- Email markup is generated by escaped TypeScript template functions; no filesystem HTML templates are used.
- Tasker application creation is atomic and rejects duplicate services, invalid dates and overlapping availability.
